# 一图成套 · GIF 表情包工坊

本技能专用于 Codex，默认使用当前会话内置图片生成工具，用户无需另配图片 API 或选择外部服务。确认参考图读取和输出文件可用即可；内置工具未开放或额度不足时说明具体阻塞。本地合成依赖由 Codex 检查与准备。运动补帧是可选能力，不等于内置图片生成，不默认安装大型模型或切换付费视频路线。

用一张主图和一个主题，交付若干独立可发送的 GIF。主图可以是照片或现成角色模板。主题规划和表演设计由模型完成，文件与编码约束由程序检查。

## 必须交付的文件与执行终点

用户调用本技能说“做表情包”“做Q版表情包”时，默认执行到独立 GIF 成品，不要求用户补说“动态”或“继续”。仅当用户明确要求静态图、只做设计或先审核某一步时，才改变交付目标或停在该节点。

最终主交付物必须是每条表情对应的独立 `.gif` 文件，并附动态预览和下载 ZIP。PNG、JPEG、WebP 静态图、九宫格、角色母版或提示词都不能替代 GIF 成品。

每次生成工具返回后，先判断实际产物，再决定下一步：
- 返回真实多帧 GIF：检查动作、数量和文件，合格后继续其余条目；无需再拆帧重画或重复合成。
- 返回静态图、角色母版或姿势页：仍处于制作中。即使图片已经显示在聊天里，也必须继续制作各条连续动作并导出 GIF，不能因此结束本轮。
- 只完成部分 GIF：保留已有结果并继续缺少的条目，不把完成的静态图数量算入动图数量。

不要询问“要不要做成动图”“是否继续合成”，也不要以“目前是静态合集，尚未完成 GIF”作为没有实际阻塞时的最终回复。不同文案的静态表情不是同一动作的连续帧；禁止轮播这些静态表情、重复同一帧或只改扩展名来满足 GIF 文件要求。

开始生成前先读[制作与工具](references/production.md)，核实参考图生成、文件读取和 GIF 合成所需能力。静态图像工具不能直接输出 GIF 不等于整条路线不可行；可用真实姿势序列加编码工具完成。若缺少必需能力、权限或达到修复上限，应明确报告具体阻塞、已完成部分和剩余条目，不以静态合集降级冒充成品，也不无限重试。

## 输入与默认值

只需角色参考图、主题。多张图且角色不明确时才询问主参考；图片不可访问时请求重新提供。现成模板直接作为造型依据，不重新选风格。真人照片尚未角色化且用户要求转换时，先做一张角色样张作为内部母版，检查身份后继续制作动作与 GIF；除非用户要求先确认，不在母版阶段等待批准。不要把照片背景默认带入。

内置37张画风参考图，使用方式与索引见[风格库](references/style-library.md)。用户上传的主图决定主体身份、外貌和关键特征；库内图只提供线条、材质、色彩、夸张方式，不能代替主图或把示例人物套给所有用户。用户已指定风格时直接选对应参考；未指定时沿用主图画风，不强制选库。每次只加载选中的样图，避免把37张全部传给生成工具。

统一画风不等于统一表情。跨条目保留身份特征与画风，按聊天含义变化眉眼、嘴形、视线、头部朝向和身体姿势；不要只换道具或文案却沿用同一种笑脸、半眯眼或歪头。母版约束身份，不锁定神态。相机、姿势与表情的连续性约束针对同一枚GIF的前后帧，不强加给整套所有条目。

未指定时：12 条，简体中文文案 2–6 个字，正方形 512px，白底；默认显示顶部深色粗圆字加白描边。用户说“不要字／无字版／纯动作”即关闭画面文字，可整套或单条关闭；仍保留内部含义与动作设计，释放原文字区，不强留空白条。用户给定的数量优先，8–16 是常见范围而非限制。用户确定的风格、字体、背景、文案与审批持续有效。

默认用语义明确的轻动效，以运动连续、无明显跳变或重影为交付目标。大动效由用户指定或由明确需要跑跳、转身的表达决定。动作幅度与流畅度分别判断：轻动效也要连续，大动效也要讲清起势、变化和收势。不把少帧轮播作为默认成品。

聊天表情包优先胸像或腰部以上半身构图，让脸、视线和手势占主要面积；需要跑跳等动作时采用大头小身体的全身Q版。参考图可以是半身，也可由全身模板重新生成半身母版，不强制先生成全身。整套保持接近的脸部显示尺寸，按动作需要决定露出范围；半身不能切掉参与动作的手或道具。

用户流程：提供参考图与主题 → skill设计文案、动作并制作 → 用户查看整套动图、提出局部修改。
- 图和表情包类型明确的制作请求直接执行，例如“用这张图做一套不想上班的表情包”。数量、文字开关或幅度未指定时采用默认值，不要求额外说“全自动”。用一条简短进度说明告知理解后开始；动作计划和首条样片由模型内部检查，不增设审批关口。
- 用户说“先看文案／先看动作／先做一张我确认”时，才按指定节点停下；已批准的不重复问。
- 仅缺失会实质改变作品的输入才追问，如多个候选角色无法判断选谁。外部费用与权限按实际工具边界处理，不推定无限预算。
- 用户只要求设计流程、讨论能力或举例说明时，交付设计与解释，不把示例句当作生成任务。

用户主图、每次生成的角色母版与审核状态放在任务目录，不自动复制进skill。assets/styles内的37张图片是用户明确授权加入的画风样图，属于此规则的指定例外；此授权不扩展到其他人物照片或上传的动作参考。

## 规划与生成

1. 看参考图，记录角色不可随意变化的特征、允许变化的表情和肢体。宠物左右花色按主体自身左右标注，另记画面位置；视角不清时不猜。具体方法见 [创作设计](references/creative.md)。
2. 按主题覆盖不同聊天用途，生成足量短文案并筛选；为每条同时写使用情境、动作、道具和笑点。不能先凑文案再套通用抖动。同义文案配同样动作时合并或替换。
3. 按协作方式展示简表或自行继续。制作前把意图写成可观察的动作变化。题材所需的笔记本、咖啡杯等可以设计新增；一旦确定，道具的数量、形状和接触关系在本条内保持一致。
4. 读取 [制作与工具](references/production.md)。当前内置工具支持直接生成 GIF 时优先使用，并核验实际文件；只有静态输出时生成真实姿势序列后合成。不要从产品宣传或模型名称推定当前会话的接口能力。
5. 新模板先做一条有代表性的小样，检查身份、动作含义、文字可读性和循环。用户要求样片审批则等批准；否则由模型检查后继续。不要先把全套都生完才发现模板漂移。
6. 按每条表演设计生成动图或连续姿势。参考图用来约束身份；本条已通过的起始姿势和道具用来约束连续性。每条一个主动作，少量必要配合动作；保持相机与尺度稳定，留足运动边距，有字时再留字区。姿势合成路线的源姿势中不写文案，仅在文字开启时后期统一加字。
7. 姿势合成路线：生成帧准备好后，按 [任务格式](references/job-format.md) 保存 render.json；运行 scripts/compose_pack.py 导出。输入必须是已经核对过的同尺寸独立帧。本脚本不会补画动作、自动切图、抠图或判断脸像不像。已直接取得 GIF 时跳过此合成步骤，进入检查与打包，不把 GIF 作为独立姿势帧传入该脚本。
8. 按 [验收](references/quality.md) 默认做快速检查：程序核对文件，正常播放浏览整套，关注身份、文案动作和循环。发现异常或用户要求精检时才展开逐帧排查，不默认保存全量逐帧 PNG。检查本身不调用生图；局部失败只修对应条目与受影响的相邻帧。默认每条最多两轮有针对性的修复，仍不合格则列明问题和可行替代，不无限重试或用静态缩放冒充成功。

## 动作标准

需要灵感时按需读取[动作参考库](references/action-library.md)索引，再选相关主题文件；共128条、16个主题，不默认加载全部。它是可选示例，不是白名单、固定词典或必走步骤；允许改编、组合和设计库外动作，不为新动作增加审批。风格库只约束画法，不把任何画风绑定到特定动作。

轻动作可以是半抬眼皮、扶眼镜、推远杯子、放下鼠标、指尖敲桌、抱住靠垫；必须能表达本条文案。呼吸缩放、整张图左右摇晃、只有粒子闪烁，不足以完成角色表演。

先判断动作过程，再决定关键姿势、过渡与时长，不固定6张或10张图作为成品。生成姿势数、补出的中间帧与最终编码帧数分开记录。优先获得连续姿势；相邻姿势可稳定对应时可运动补帧，出现重影、拉扯或接触错误时补画过渡或重设计该段。合成脚本不含运动补帧能力，具体方法见制作参考。停顿用于表演节奏；重复帧、加快帧率、叠化不等于补全动作。

循环按物理和语义设计：挥手可往返，喝水和合电脑不能直接倒放。允许用停顿、遮挡或设计好的复位衔接，检查实际首尾播放；不强制每条重复保存相同首尾帧。

## 交付与完成

展厅、动态浏览页与下载清单中的展示名称使用表情含义，不自动追加“有字版／无字版”；是否显示文字作为内部排版设置保留。

交付独立 GIF、动态浏览页、下载 ZIP 和简要验收结果；可按需附 PNG、WebP 与制作源文件。用户主要验收“形象对不对、动作贴不贴、播放顺不顺”，不必阅读编码报告。包内默认不含用户原始参考图、临时生成图或本机绝对路径。有字版固定字幕位置、字体、描边和字号；字体缺失时寻找可用且覆盖中文的替代，不假称使用了指定粗圆字体。

完成数量按合格条目计算。技术通过、视觉通过和用户接受分别记录。没有实际观看正常播放或存在失败条目时，说明具体未完成项，不能把可解码当成动画质量通过。

结束前必须核对实际交付物：文件确实为 GIF 格式而不是仅有 `.gif` 扩展名；每枚可解码为多个不同帧且呈现本条角色动作；合格 GIF 数量等于用户要求或已采用的默认数量；预览页和下载链接指向实际文件。最终回复提供 GIF／整套下载入口，静态总览只能作为附图。全部通过才报告整套完成。只有母版、静态合集或提示词时仍处于制作中，工具可用且没有实际阻塞就继续执行。正常播放待验收或存在失败条目时按实际状态交付，不计作全部通过。

继续/追加沿用任务状态；“只改第3条文案”不重画全部；“增加4条”保留旧编号并扩展；“改动作”保留已接受的身份、风格和文字。
